# 実機マルチアカウント煙テスト手順（Manual Multi-Account Smoke Test）

対象: アカウント並列対応（Phase 6.x）の最終確認。
自動テストでは検証できない、**実 Discord クライアント＋実 CDP＋実プロキシ**の組み合わせを手動で確認する。

---

## 0. 検証したい主張

| # | 主張 | 対応シナリオ |
|---|---|---|
| 1 | アカウント A のリクエストが B のトークン／super-properties／プロキシ資格情報／CDP ポートを使うことはない | S3〜S6 |
| 2 | 同一クエスト ID を A/B で独立に実行でき、片方の停止・エラーが他方に影響しない | S3, S4 |
| 3 | アカウント内の activity/request/レート制限は独立。プロセス/CDP リソースは正しく排他される | S3, S5 |
| 4 | CDP ポートの lease は検証済みアカウントまたは直接操作のどちらか一方のみが保持し、競合は変更前に失敗する | S5 |
| 5 | 保存プロファイルは再起動後オフライン扱いで、認証済み操作はできない | S7 |

---

## 1. 事前準備

- [ ] Discord デスクトップを **CDP 有効**で 2 つ起動できる状態にする（ポート例: `9223` = A、`9224` = B）
  - アプリの「CDP で起動」機能を使い、既存 Discord が居る場合は競合解決されることを確認
- [ ] テスト用アカウント A / B を用意（片方はクエスト未完了のものがあると確認しやすい）
- [ ] 任意: A 用に到達可能な HTTP プロキシを 1 つ用意（S6 で使用）
- [ ] アプリを起動（開発時は `corepack pnpm tauri:dev`）
- [ ] 失敗時のためにアプリのログ出力を開いておく

---

## 2. シナリオ

### S1. ログインとプロファイル

**手順**
1. A を CDP でログイン（ポート `9223`）
2. アカウントメニューを開く
3. B を「アカウント追加」からログイン（ポート `9224`）

**期待結果**
- [ ] アカウント一覧に A / B が並び、アクティブなアカウントが視覚的に判別できる
- [ ] 両方とも「認証済み」として表示される（オフラインアイコンが出ない）
- [ ] ヘッダーのレイアウトがずれない

### S2. アカウント切替

**手順**
1. A → B へ切替
2. B → A へ切替
3. クエスト一覧が切替直後に一瞬古い内容を出すか観察する

**期待結果**
- [ ] 切替後、クエスト一覧・実行中クエストが**切替先のもの**に置き換わる
- [ ] A の取得結果が遅れて返ってきても B の画面に混入しない
- [ ] 切替中は切替／削除操作が無効化される（busy）

### S3. 同一クエスト ID の並行実行

**手順**
1. A で動画クエスト X を開始
2. アカウントを B に切替え、同じクエスト X を開始
3. 進捗パネルで両方の実行が見えるか確認

**期待結果**
- [ ] A・B それぞれで X が実行され、片方が他方を上書きしない
- [ ] 進捗パネルに実行中のアカウント（アバター＋名前）が表示される
- [ ] 片方だけを停止でき、もう片方が継続する（S4）

### S4. 停止の分離

**手順**
1. S3 の状態で、B 側の停止ボタンを押す

**期待結果**
- [ ] B の X のみ停止し、A の X は継続する
- [ ] 停止後も A 側の表示・進捗が壊れない

### S5. CDP ポート競合の拒否

**手順**
1. A を `9223` でログインし、**同ポートを使う長時間の CDP クエストまたは手動ゲーム spoof を開始する**
2. A の作業が続いている間に、B から `9223` を使う CDP クエスト／操作、または同ポートのデスクトップ再起動を試す
3. A の作業を停止し、CDP の後片付けが完了したことを確認する

**期待結果**
- [ ] A が lease を保持中は、B の操作／再起動が変更前に `cdp_port_conflict` 系のエラーで失敗する
- [ ] A の実行・ログイン状態は変化しない（停止されない）
- [ ] A の作業終了後は `9223` の lease を新たな操作が取得できる。ただしデスクトップ側がまだ A でログイン中なら、B の**認証対象**操作は `account_mismatch` で拒否される

**注意:** ログインが完了しただけのアイドル状態ではポートの永続バインドはない。競合試験は必ず A の CDP 作業が継続中に行う。

### S6. プロキシ分離

**手順**
1. 設定 → アカウント → A のプロキシを「カスタム」にしてプロキシを保存（資格情報は入力のみ）
2. B は「グローバル継承」または「システム」のままにする
3. A・B それぞれでクエストを開始し、疎通することを確認
4. B の設定画面で A のプロキシ資格情報が表示されないことを確認

**期待結果**
- [ ] A はカスタムプロキシで通信できる
- [ ] B は A のプロキシ設定の影響を受けない
- [ ] 保存後に資格情報（ユーザー名／パスワード）が画面に再表示されない（「保存済み」表示のみ）
- [ ] オーバーライドを解除すると A がグローバル継承に戻る

### S7. 再起動後のオフラインプロファイル

**手順**
1. アプリを終了し、Discord を全て閉じる
2. アプリを再起動し、アカウントメニューを開く

**期待結果**
- [ ] 保存済みアカウントは一覧に出るが「サインインが必要（オフライン）」として表示される
- [ ] その状態で認証が必要な操作を行うと `Not logged in` 系のエラーになる（成功しない）
- [ ] オフラインのアカウントを選んでも、認証済みとして表示されない

### S8. アカウント削除

**手順**
1. A・B の両方でクエストを実行中の状態をつくる
2. B を削除（確認ダイアログで承認）

**期待結果**
- [ ] B の実行中クエストと手動 spoof が停止してから削除される
- [ ] B のプロキシオーバーライド／資格情報参照も削除される
- [ ] A の実行・設定は一切変化しない
- [ ] アクティブだったアカウントを削除した場合、アクティブ表示が破綻しない

### S9. 終了処理

**手順**
1. A・B でクエストを実行したままアプリを終了

**期待結果**
- [ ] 実行中クエストが停止し、終了がハングしない
- [ ] 次回起動時に残存 CDP lease が残っていない（ポートが再利用できる）
- [ ] 停止に失敗した場合は終了が失敗として扱われ、再試行できる

---

## 3. 失敗時の確認箇所

- アプリのログ（起動コンソール／ログ出力）で `cdp_port_conflict` / `account_mismatch` / `resource_busy` を検索
- CDP ポートの生存確認: `http://127.0.0.1:9223/json/version`（A）/ `9224`（B）
- プロキシ設定ファイル: アプリの設定ディレクトリ配下 `proxy.v1.json`（`accounts` セクションにオーバーライドのみが入り、**資格情報の実体は OS 資格情報ストア**）
- アカウント一覧: アプリの設定ディレクトリ配下のアカウントファイル（トークンは保存されない）
